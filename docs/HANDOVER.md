# 자율운항 선박 설계 자동화 PoC — 통합 시스템 명세 인수인계 문서

> 작성: 2026-07-28. 이 문서는 설명서 제작을 맡을 외부 AI에게 넘기는 사실 자료임.
> **작성 규칙 (문서 제작 AI에게):** 아래 내용은 전부 구현·측정된 사실 또는 "계획"으로 명시된 항목임.
> 새 숫자를 지어내지 말 것. 사실과 계획을 구분해 서술할 것. 불명확하면 불명확하다고 쓸 것.
> 저장소: https://github.com/unmatsutake377-rgb/ship-ai-design-project (커밋 이력·문서 전부 공개)

## 1. 프로젝트 개요

- **최종 목표:** 사용자가 운항 목적(용도·탑재량 등)만 입력하면, AI/최적화가 물리적으로 검증된 최적 선형 후보들을 생성·제시하고, 선택된 설계를 ROS2/Gazebo 시뮬레이션에 투입해 자율운항 알고리즘을 테스트할 수 있는 End-to-End 자동화 파이프라인 (개념 증명).
- **주요 타겟:** 1~3m급 소형 무인수상정(USV). 현 단계는 **저속 배수량형(길이 Froude 수 Fn < 0.4)만 완전 지원** — 저속 조사용 USV가 데모 시나리오. 반배수량·활주(고속)는 Phase C 계획.
- **성격:** 학부 2학년 수준 오너의 학습 프로젝트. 모든 물리 모듈은 "정답지 있는 검증"(해석해·문헌·독립 구현 대조)을 통과해야 병합되는 규율. 현재 **pytest 149개 전부 통과** 상태.
- **개발 환경:** macOS Apple Silicon, Python 3.13, Docker Desktop (ROS2용). 저장소 main 브랜치 단일 진실.

## 2. 전체 시스템 아키텍처

### Phase A — 선형 설계·검증·최적화 (완료)

파이프라인 순서 (`python -m src.pipeline --payload 100 --purpose survey` 한 줄로 전 과정):

| 모듈 | 역할 | 검증 근거 |
|---|---|---|
| core/regime | 3체계 속도 판정 (배수량 Fn<0.4 / 반배수량 / 활주 Fn≥1.0 또는 Fn∇≥3). C-2(07-30)로 **세 체계 전부 설계 지원** — 거절은 체계가 아니라 물리·카탈로그 사유(활주 평형 불성립, 모터 부족)로만 발생 | 경계 일관성 테스트 |
| ai/presets (#25) | 용도 선택 → 기본 순항속도 자동 (실선 순항 중앙값 — survey는 6척 근거 1.54 m/s). --speed 직접 지정 우선 | 데이터/개략 출처 표시 |
| ai/dimension_estimator | 치수 추정 — 실선 USV 제원 통계 (수집 9척 중 단동 조사선 5척 기반: L/B≈2.0, B/T≈3.7). 사용자가 --loa로 크기 개입 가능, 적재-크기 모순 시 필요 최소 길이 제시하며 거절 | 실선 데이터 CSV (출처·등급·물리 관문 자동 심사) |
| ai/hull_generator | 일반화 Wigley 파라메트릭 선형 (Cp·Cm 지수 역산, watertight 메쉬). Cb 도달범위 밖은 명시적 거절 | 부피 해석해 (Cb·L·B·T) 2% 내 |
| physics/weights | 중량·무게중심 분포모델: 구조(면밀도×표면적)+실물 추진계+적재. KG·LCG·Izz 산출, 트림 경고 | 자기일관 폐합 테스트 |
| physics/hydrostatics | 평형 흘수 역산(아르키메데스, 이분법), KB·BM, GM/B 밴드(0.04~0.40)·건현 필터. 불합격은 사유 리포트 (조용한 폐기 금지) | 직육면체 바지선 해석해 |
| physics/resistance | ITTC-57 마찰 + Michell 박선 조파. **해석판(Wigley 전용)과 메쉬판(임의 형상) 2종** — 메쉬판은 해석판 대비 0.3~0.6% + Ship-D 원저자 독립 구현 대비 비 0.93~1.00으로 **이중 검증** | Wigley 문헌 벤치마크 Cw=1.61e-3 @ Fn 0.316 |
| physics/propulsion | 실물 모터 카탈로그(Blue Robotics T200/T500, Torqeedo Ultralight 403 — 공식 스펙) 이산 선택, 여유율 2.0, 차동 2발. 배터리 = 전력×항속/효율(0.4)/DOD(0.8)/150Wh·kg⁻¹ | 선택 로직·부족 시 거절 |
| pipeline (설계 나선) | 중량→흘수→저항→모터·배터리→중량 고정점 반복 (데모 4회 수렴). 추진계를 고정비율 가정(27kg)에서 실측(4.5kg)으로 교정 — 전체 중량 179→148kg 사례 | 수렴·중량 폐합 |
| physics/coefficients | Fossen 3자유도 계수: Clarke(1983) 회귀 + 저항곡선 미분(Xu). **대형선 외삽 경고 상시 + 범위 밖 클램프 플래그** (B/L~0.5에서 음수 관성 발산 버그를 잡은 이력) | 수계산 고정값·차원 스케일·유한차분 대조 |
| sim_adapters/python_sim | 웨이포인트 추종 시뮬 (lookahead LOS + 코너 감속 + **고유값 판별 게인 사다리** — 통통한 선체는 방향 불안정이라 필수). 사각 코스 완주 62s, 직선 이탈 σ 0.05m | 물리 불변량 4종 + 경로 품질 + 폐루프 안정 |
| hitl | 1~5점 로깅(보조) + **쌍대비교 ELO(주 인터페이스)** — 이력 재생 파생, 제로섬, 이변 가중. 오너 실평가 2건 기록 (선호: 경량형>안정형>저항최소형) | ELO 성질 테스트 7종 |

**최적화 계층 (M5 계열, 완료):**
- **M5b-2 1차:** NSGA-II(pymoo) × Wigley 4변수 공간 × 물리 직접 평가 → 파레토 24척 (저항 7.0~27N ↔ 중량 140~155kg, 목적 3축: 저항·중량·안정여유)
- **M5a:** MIT Ship-D 데이터셋(합성 파라메트릭 3만 척, 45파라미터, 전 척 LOA=10 정규화) 연동 — 형상만 상사 축소로 전이, 성능 라벨은 자체 물리로 재계산 (원칙)
- **M5b-2 2차:** Ship-D 무작위 300척 선별 평가 (통과 134, 파레토 11). **핵심 발견: 저속 임무에선 Wigley(수학 선형)가 저항 우세, Ship-D(실선형)는 중량 우세 — 임무 속도가 선형 계열의 승자를 결정**
- **M5b-1:** torch(MPS) 2헤드 MLP 대리모델 → 3만 척 가상 전수 예측 → 상위 80척 실물리 재검증 → 합산 파레토 15척 (대리모델 발굴 6척). 대리모델은 후보 추천 전용 — **최종 수치는 항상 실물리** 원칙
- 45차원 직접 생성 최적화는 의도적으로 보류 (무작위 벡터 대부분이 자기교차 — 원저자 제약 49개의 존재 이유). ShipGen류 확산모델도 보류 (목적이 다양성 생성이 아니라 요구조건 최적해)

### Phase B — ROS2/시뮬레이션 통합 (B-1 완료, 진행 중)

- **환경 결정 (확정):** Mac Docker로 개발·검증, 고부하 실행은 추후 Windows PC + WSL2 (컨테이너 설정 공유 — 갈아타기가 아니라 실행 장소 추가)
- **B-1 (완료):** ① ros:jazzy 이미지(arm64 네이티브 — 에뮬레이션 없음) 토픽 pub/echo 왕복 확인 ② `ros2_export` 어댑터: report.json → URDF(질량·관성 3축·메쉬) + **유체계수 YAML**(부가질량·감쇠·추력기 배치, 부호 규약 명시 — URDF만으로는 유체역학이 전이되지 않는다는 설계 원칙) ③ 산출 URDF가 컨테이너 내 check_urdf 통과 ("Successfully Parsed XML")
- **B-2 (다음):** gz sim(Gazebo) 컨테이너에 선체 스폰 + 부력·유체 플러그인 연결
- **B-3 (계획):** 차동추력 제어 이식 (python_sim의 LOS·고유값 게인 재사용), 자율운항 알고리즘 테스트베드화

### Phase C — 확장 계획 (설계만 존재, 미착수)

- 반배수량 체계 (Fn 0.4~1.0): 트랜섬 선미 파라메트릭 계열 + Compton/NPL류 회귀 — 실선 USV 주 운항 영역
- 활주 체계 (Savitsky) — 고속 보트
- OpenFOAM CFD 훅: 파레토 상위 후보만 고정밀 해석 → 라벨 피드백 (능동 학습)
- 용도별 파레토 목적 가중 프리셋(#25 2단계), 레저·화물 카테고리 추가

## 3. 데이터 흐름도

```
[입력] 용도(survey/patrol/workboat) + 탑재량 kg  (+선택: 길이 --loa, 속도 --speed, 항속 --endurance)
   ↓
[P1: 제약 세팅] 용도 프리셋(속도=실선 순항 중앙값) → 실선 통계 치수 → 3체계 판정
                (배수량=Wigley / 반배수량=트랜섬 / 활주=데드라이즈+Savitsky)
   ↓
[P2: 설계·검증] 체계별 선형 생성 → 설계 나선(중량↔흘수↔저항↔실물 모터·배터리 수렴)
                → 정역학 필터(GM 밴드 — 활주는 상한 완화 1.50·건현) → Fossen 계수
   ↓
[P2b: 대규모 탐색] NSGA-II(Wigley 공간) / Ship-D 선별 + 대리모델 3만 척 스캔
                   → 상위 후보 실물리(Michell 메쉬판) 재검증 → 합산 파레토 전선
   ↓
[P3: 인간 선택] 파레토 후보 쌍대비교("어느 쪽이 나은가?") → ELO 랭킹 누적
                (점수제보다 초보 평가자에게 신뢰성 높다는 오너 결정)
   ↓
[출력] 선형 STL + 검증 리포트 JSON(치수·중량·GM·저항·모터·계수·근거 출처 전부 포함)
       + 파레토 CSV/플롯 + ROS2용 URDF + 유체계수 YAML + 웨이포인트 궤적 플롯
```

## 4. 인지된 시스템 한계 (Known Issues & Tech Debt) — 전부 코드/문서에 명시됨

1. **Michell 박선이론 한계:** 트랜섬 선미 뒤 유동 박리저항 미모델 → Ship-D류 트랜섬 선형의 저항은 과소평가 가능. 잔잔한 물 가정 — 내항성·슬래밍 미평가 (Phase B 파도/Phase C CFD 영역). 얇은 배 가정 — B/T 큰 바지선형에서 신뢰 저하.
2. **Clarke 조종 계수 외삽:** 대형 상선(B/L 0.1~0.2) 회귀를 USV(B/L~0.5)에 외삽 — 상시 경고 플래그 + 음수 관성 방지 클램프(발동 항 기록). 실제로 클램프 없을 때 시뮬 발산 사고 이력 있음.
3. **대리모델 데이터 부족:** 실측 라벨 ~380척으로 45차원 학습 — 회귀 R² 저조 (정직 기록됨). 초기에 탈락 표본을 저장 안 하는 라벨 결손 버그가 있었고 수정됨. 계획: 선별 반복으로 라벨 축적 → 재학습 (능동 학습 루프 — 원안 Step 5).
4. **중량/무게중심 단순화:** 점질량 3성분 + VCG/LCG 비율 가정 (상수 명시). 종강도(굽힘)·자유표면 효과 미고려 — PoC 범위 밖 선언.
5. **카테고리 데이터 공백:** patrol은 배수량형 실선이 시장에 없어(순찰=고속 임무) 개략값 fallback — Phase C에서 해소 예정. workboat 표본 1척.
6. **목적함수 불완전:** 저항·중량·안정여유 3축만 — 실무 설계 변수(갑판 면적, 운송 폭, 승차감, 제작성)는 미포함. 최적화기가 실선과 다른 비율(L/B 3.9 vs 시장 2.0)을 선호하는 현상으로 실증됨. Ship-D의 가우스 곡률·MaxBox 지표가 제작성·공간 대리값 후보.
7. **Ship-D 라이선스:** 원저장소에 라이선스 파일 없음 → 코드·데이터를 git 제외 폴더에 두고 경로 참조만 (재배포 금지). 문서 제작 시에도 Ship-D 원본 재배포 금지 유지할 것.
8. **시뮬레이션은 정성 검증용:** 오일러 적분, 교차항 일부 생략, 프로펠러 즉답 가정 — 정량 신뢰는 Phase B(VRX/Gazebo)·C(CFD)의 몫.
