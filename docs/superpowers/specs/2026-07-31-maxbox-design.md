## 1. 결정 (오너)

**MaxBox = 제약 + 여유 표기 (B+C안).** 오너 논리 그대로: "용도는
사용자의 마음(취향의 영역), 우리는 그 배가 실제로 구현되는지
판단(물리의 영역) — 그러니 충분하게 맞추는 것." 목적함수(4목적) 안은
기각 — 우리 용도(조사·순찰 USV)에서 공간은 문턱이지 최대화 대상이
아니고, 파레토가 4차원이 되면 사람 선택(HITL)이 무너짐.

메우는 구멍: 기존 파이프라인은 짐을 **무게로만** 검사 (아르키메데스)
— 무게는 실려도 부피가 안 들어가는 배를 걸러내지 못했음.

## 2. MaxBox 계산 (`src/physics/maxbox.py`)

선체 내부 최대 직육면체의 이산 탐색:
- 상자 가정: 중심선 대칭, 갑판까지: [x₀,x₁] × 2w × [z₀, depth].
  보통 선형은 아래로 좁아지므로 폭 병목은 상자 바닥 z₀에서 발생
- z₀ 격자 스캔: 각 z₀에서 단면 반폭 지형도 w(x) 산출(메쉬 단면) →
  **히스토그램 최대 직사각형**(고전 알고리즘, 손계산 정답지 있음)으로
  최적 [x₀,x₁]×2w → 부피 = 면적 × (depth−z₀). z₀ 전 격자 중 최대
- 반환: BoxReport(length, width, height, volume, z0)
- 검증: 직육면체 바지선 = 전체 부피 (해석 정답), Wigley = 중앙 배치
  경향 + 부피 < 선체 부피

## 3. 파이프라인 연결

- 부피 입력: `--payload-volume` [m³] 직접 입력 우선, 생략 시
  용도별 화물 밀도 프리셋으로 환산 — PAYLOAD_DENSITY = {survey: 400,
  patrol: 400, workboat: 600} kg/m³ (**개략 가정, 명명 상수** — 실측
  근거 없음, #17 수집 대상임을 리포트에 표기)
- 필터 4번째 검사: `payload_space` = (짐 부피 ≤ MaxBox 부피) —
  hydrostatics checks dict에 추가가 아니라 **run_pipeline 층에서 합성**
  (정역학 모듈은 물에 뜨는 문제만 담당 — 책임 분리)
- 리포트: maxbox {length, width, height, volume, payload_volume,
  margin_ratio, density_assumed} + passed에 반영 + CLI 요약 출력
- 이번 회차 제외 (후속 기록): 최적화기·Ship-D 선별기의 공간 제약 반영

## 4. 검증

- 히스토그램 최대 직사각형: 손계산 케이스 pytest
- 바지선 MaxBox = 선체 상자 그대로 (해석 정답)
- Wigley: 부피 양수, 선체 부피 미만, 중앙 근방 배치
- 파이프라인: 초대형 부피 요청 → payload_space False → passed False /
  기본 밀도 경로 → 기존 데모 통과 유지
