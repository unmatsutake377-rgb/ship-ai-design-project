## 1. 배경 (학부 2학년 눈높이)

이 프로젝트의 본질은 "목적(속도·짐·용도)을 넣으면 배가 나온다".
지금까지 결과는 터미널 텍스트와 문서로만 존재 — 시연 상대(교수·
친구)가 체험할 창구가 없다. Streamlit은 파이썬 몇 줄로 브라우저
UI를 만드는 라이브러리라, 기존 파이프라인을 **임포트 재사용**
(새 물리 0줄)하면서 화면만 입히면 된다.

## 2. 구조

```
app/
  main.py               # 홈 — 프로젝트 소개·8중 게이트 요약
  pages/
    1_라이브_설계.py      # 1단계 회차
    2_갤러리.py           # 2단계 회차
  ui/
    mesh_view.py         # trimesh → plotly Mesh3d 변환
    gates.py             # 리포트 dict → 신호등 카드 데이터
    cards.py             # 성적표 카드 + 학부 2학년 툴팁 사전
```

- 실행: `streamlit run app/main.py` (PYTHONPATH=프로젝트 루트)
- `app/ui/*`는 **streamlit 비의존 순수 함수** — 단위시험 대상.
  streamlit 렌더 코드는 pages/에만 (수동 브라우저 검증).

## 3. 1단계 — 라이브 설계 페이지

- **입력**: 용도 라디오 4종 (survey/patrol/workboat/cargo) +
  속도·짐 슬라이더 (용도별 실현가능 대역 연동 — 기존
  feasible_speed 재사용) + 단동/쌍동 토글 + 고급 접기
  (hull_source auto/shipd/formula, 게이트 on/off 플래그)
- **실행**: 버튼 → `run_pipeline(goal, tmpdir, ...)` —
  `st.status`로 나선 단계 실황 (치수 추정 → 선형 생성 → 정역학
  → 저항 → … → 8중 판정). `st.cache_data`로 동일 입력 재실행
  방지. 결과 dict는 `st.session_state` 보관.
- **결과 4요소**:
  1. **3D 선형 뷰** — plotly Mesh3d 회전·확대 (로컬 열람이라
     라이선스 안전)
  2. **8중 게이트 신호등** — 합격 초록 / 불합격 빨강 / **정직
     스킵 회색** (관례 그대로 — "데이터 없음 ≠ 불합격" 문구
     병기)
  3. **성적표 카드** — 치수·GM·저항·엔진·EEDI·CII·수송단가 +
     용어 툴팁 (쉬운 설명서 용어 사전 재사용)
  4. **설계 과정 실황** — 나선 반복·게이트 판정 로그
- **오류 처리**: 파이프라인 예외 → `st.error` + 정직 사유
  (죽지 않음). 대형 실행 수십 초 대기는 status 실황이 흡수.

## 4. 2단계 — 갤러리 페이지

- **파레토 전선 탐사기**: outputs/ 최신 전선 CSV 산점도 (단가
  vs 속도) — 점 클릭 시 상세 (치수·EEDI·roll RMS·3D 선형).
  **데이터 소스는 "가장 최신 완전 검증 전선" 규약** (현재
  pareto_large_v4_evo.csv + pareto_v4_full_recheck.csv 병합 —
  완전 검증 70척, 차기 진화 완주 시 교체 — §7).
- **설계 지도 히트맵**: 속도×짐 격자 수송단가·합불 (기존 12점
  design_map_12.json, 필요 시 고해상 재계산 자산으로 교체)
- **항해일지 연대기**: 30일 회차 타임라인 (게이트 5중→8중·시험
  증가 그래프·실패 박물관 하이라이트) — worklog 요약 정적 데이터
- **파도 타는 배 GIF**: outputs/wave_exp/wave_ride.gif 등 렌더
  자산 코너
- ⚠ 전선 CSV·렌더는 outputs/ (커밋 금지) — 앱은 **읽기만**,
  자산 없으면 정직 안내 ("자산 없음 — 실행 방법" 표기).

## 5. 시험 전략

- `tests/test_app_ui.py`: ui/ 순수 함수 단위시험 — 메쉬→plotly
  변환 (정점·면 수 보존), 리포트→신호등 가공 (합격/불합격/스킵
  3태 매핑), 카드 포맷. 파이프라인 자체는 기존 436개가 담당.
- streamlit 화면은 수동 검증 (로컬 브라우저 열람 — 오너 눈이
  정식 검증 단계 관례).

## 6. 하지 않는 것 (YAGNI)

- 인터넷 배포·인증·다중 사용자 (절대 없음 — 오너 확정)
- 앱 내 NSGA 실행 (장기 작업은 nohup 관례 유지 — 앱은 결과만)
- Gazebo/ROS2 연동 화면
- 편집 가능 파라미터 45종 노출 (목적 3입력 철학 유지)

## 7. 갱신 훅 — 살아있는 문서 규약

본체 체계가 바뀌면 **회차 마감 4축에 이 스펙 갱신을 포함**한다:

| 본체 변화 | 스펙 반영 지점 |
|---|---|
| 게이트 수·판정 체계 변경 (예: 9중) | §3 신호등 요소 수 |
| 새 전선/재검 CSV (NSGA v3 완주 등) | §4 "최신 완전 검증 전선" 파일명 |
| 내항 기준·성적표 항목 변화 | §3 성적표 카드 목록 |
| 새 선체 갈래 (쌍동 외 추가) | §3 입력 토글 |
| 용어 사전 증보 | §3 툴팁 소스 |

구현 착수 시점에 이 표 기준으로 최신 상태 확인 후 계획 수립.
